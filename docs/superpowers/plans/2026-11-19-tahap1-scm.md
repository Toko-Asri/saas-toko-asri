# Toko Asri Tahap 1 (SCM) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aplikasi Next.js + Supabase dengan login berperan dan modul SCM lengkap (pemasok, produk, lokasi/suhu, batch, pesanan pembelian, penerimaan barang, saran pembelian) plus README setup Supabase.

**Architecture:** Skema dan logika kritis di Postgres (`supabase/migrations`), dijaga RLS per peran. Next.js App Router (Server Components + Server Actions) hanya memanggil tabel/RPC lewat `@supabase/ssr`. Aturan murni (izin menu, status kedaluwarsa) dipisah di `src/lib` agar dapat diuji unit.

**Tech Stack:** Next.js (App Router) + TypeScript + Tailwind, `@supabase/supabase-js`, `@supabase/ssr`, Vitest, Postgres 16 lokal untuk uji SQL.

**Spec:** `docs/superpowers/specs/2026-11-19-toko-asri-design.md`

## Global Constraints

- UI Bahasa Indonesia; mata uang Rupiah (`Intl.NumberFormat('id-ID', {style:'currency', currency:'IDR', maximumFractionDigits:0})`).
- Peran enum persis: `pemilik`, `kasir`, `staf_gudang`.
- Akses tahap ini: `pemilik` semua; `staf_gudang` inventori + pembelian + master SCM; `kasir` hanya baca stok produk.
- Migration hanya ditulis di `supabase/migrations/`, seed di `supabase/seed.sql`; **jangan dijalankan ke Supabase pengguna**. Uji SQL hanya di Postgres lokal sementara.
- Tidak ada deploy publik. Secret tidak di-commit; `.env.local` di `.gitignore`, sediakan `.env.example`.
- Setiap tugas selesai dengan `npm run build` lulus (kecuali tugas SQL murni) dan commit; commit diakhiri trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` dan `Claude-Session: https://claude.ai/code/session_01NjswzVeNpJvCu4pynPEeRZ`.

### Task 2: Migration skema SCM, RLS, trigger, RPC (diuji di Postgres lokal)

**Files:** Create `supabase/migrations/20261119000100_scm_schema.sql`, `supabase/tests/00_auth_stub.sql`, `supabase/tests/scm_test.sql`.

**Interfaces:**
- Produces tabel: `profiles(id uuid pk → auth.users, nama text, peran peran_enum)`, `suppliers(id, nama, kontak, telepon, alamat, aktif bool)`, `storage_locations(id, nama, tipe text check in ('freezer','chiller','kering'), suhu_min numeric, suhu_maks numeric)`, `products(id, sku unique, nama, satuan, supplier_id, harga_beli, harga_jual, min_stock int, reorder_qty int, aktif)`, `batches(id, product_id, location_id, kode_batch, qty int check >=0, tgl_kedaluwarsa date, tgl_masuk date default current_date)`, `purchase_orders(id, supplier_id, status in ('draft','dipesan','diterima','dibatalkan'), dibuat_oleh, created_at)`, `purchase_order_items(id, po_id, product_id, qty_pesan int check >0, qty_diterima int default 0, harga_beli)`, `purchase_suggestions(id, product_id, qty_disarankan, status in ('terbuka','dipesan','diabaikan'), created_at)`.
- Fungsi: `current_peran() returns peran_enum` (security definer, baca `profiles` untuk `auth.uid()`); `refresh_suggestion(p_product uuid) returns void`; `create_po_from_suggestion(p_suggestion uuid) returns uuid` (membuat PO `draft` untuk supplier produk, 1 item = `qty_disarankan`, tandai saran `dipesan`); `create_po(p_supplier uuid, p_items jsonb) returns uuid` dengan `p_items = [{product_id, qty, harga_beli}]`; `receive_goods(p_po uuid, p_items jsonb) returns void` dengan `p_items = [{item_id, qty, location_id, kode_batch, tgl_kedaluwarsa}]`.
- Trigger `batches` after insert/update/delete memanggil `refresh_suggestion`.
- Consumes: skema `auth.users` dan `auth.uid()` (di Supabase asli; di uji lokal dari stub).

- [ ] **Step 1:** Siapkan Postgres lokal sementara (mis. `pg_ctlcluster`/`initdb` di direktori scratchpad), buat DB `asri_test`, muat `00_auth_stub.sql` (skema `auth`, tabel `auth.users(id uuid)`, fungsi `auth.uid()` membaca `current_setting('request.jwt.claim.sub', true)`, role `authenticated`).
- [ ] **Step 2:** Tulis `scm_test.sql` (skrip psql yang `RAISE EXCEPTION` bila asersi gagal) dengan kasus: (a) `create_po` dengan `[]` atau qty 0 → error; (b) `receive_goods` penuh membuat batch dan mengubah status PO ke `diterima`; (c) memanggil `receive_goods` lagi untuk item yang sama → error (tak ada sisa); (d) qty_diterima > qty_pesan → error; (e) batch total = `min_stock` untuk produk → tepat satu saran `terbuka`, memanggil `refresh_suggestion` lagi tidak menambah baris; (f) menerima barang hingga stok > `min_stock` menutup saran (status `diabaikan`); (g) `create_po_from_suggestion` menandai saran `dipesan`; (h) sebagai peran `kasir` (set `request.jwt.claim.sub`) `insert` ke `suppliers` ditolak RLS, `select` pada `batches` diizinkan.
- [ ] **Step 3:** Jalankan `psql -v ON_ERROR_STOP=1 -f supabase/tests/scm_test.sql` → harus **gagal** (skema belum ada).
- [ ] **Step 4:** Tulis migration sesuai Interfaces: enum `peran_enum`, tabel, RLS (`pemilik` semua; `staf_gudang` CRUD tabel SCM; `kasir` select `products`, `batches`, `storage_locations`; `profiles` select baris sendiri + pemilik semua), trigger, dan RPC (RPC `security definer` dengan pengecekan `current_peran() in ('pemilik','staf_gudang')`). `receive_goods` mengunci baris item (`for update`) dan memvalidasi sisa = `qty_pesan - qty_diterima`. `refresh_suggestion`: bila total stok ≤ `min_stock` dan tak ada saran `terbuka` → insert `reorder_qty`; bila total stok > `min_stock` → tutup saran terbuka. Tambah trigger pembuatan baris `profiles` otomatis TIDAK dilakukan (peran diberikan manual, lihat README).
- [ ] **Step 5:** Muat migration ke DB lokal, jalankan ulang `scm_test.sql` → semua lulus tanpa error.
- [ ] **Step 6:** Commit `feat(scm): skema database, RLS, trigger saran pembelian, RPC`.
