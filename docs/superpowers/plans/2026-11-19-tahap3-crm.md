# Toko Asri Tahap 3 (CRM) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Modul CRM: data pelanggan, riwayat belanja, poin dan tier loyalitas, serta segmentasi pelanggan; transaksi kasir yang memilih pelanggan otomatis memperbarui profil pelanggan dalam transaksi database yang sama (integrasi ERP → CRM).

**Architecture:** Sama seperti Tahap 1–2: logika kritis di Postgres. `checkout` diperluas dengan parameter pelanggan opsional; di transaksi yang sama ia mengunci baris pelanggan, menghitung poin, menambah total belanja, dan menaikkan tier. Kolom hitungan (poin, total belanja, tier, dst.) tidak dapat ditulis langsung oleh aplikasi: hak tulis ke `customers` dibatasi per kolom. Segmentasi adalah view SQL; Next.js hanya antarmuka. Perubahan skema HANYA lewat file migration baru (Tahap 1–2 sudah dijalankan pengguna di Supabase demo).

**Tech Stack:** Next.js 16 (App Router, `proxy.ts`), TypeScript, Tailwind, `@supabase/ssr`, Vitest, Postgres 16 lokal untuk uji SQL.

**Spec:** `docs/superpowers/specs/2026-11-19-toko-asri-design.md` (Tahap 3: aturan poin dan tier); lanjutan dari `docs/superpowers/plans/2026-11-19-tahap2-erp.md`.

## Global Constraints

- UI Bahasa Indonesia; Rupiah lewat `formatRupiah`, tanggal lewat `formatTanggal`; "hari ini" selalu tanggal **Asia/Jakarta** (`hariIniJakarta()` di TS, `(now() at time zone 'Asia/Jakarta')::date` di SQL).
- **Aturan loyalitas (usulan di spec, nilai tetap untuk tahap ini):** 1 poin per Rp10.000 belanja, dibulatkan ke bawah per transaksi (Rp9.999 → 0, Rp10.000 → 1, Rp19.999 → 1). Tier dari **total belanja kumulatif**: `reguler` < Rp500.000 ≤ `silver` < Rp2.000.000 ≤ `gold` (batas bawah termasuk tier atas: tepat Rp500.000 = silver). Tier tidak pernah turun. Konstanta ini didefinisikan sekali di SQL (`tier_dari`, `poin_dari`) dan dicerminkan di `src/lib/loyalty.ts`; kedua sisi diuji dengan angka yang sama.
- **Aktivitas pelanggan (WIB):** `baru` = belum pernah belanja dan terdaftar ≤ 30 hari; `aktif` = belanja terakhir ≤ 30 hari lalu; `berisiko` = 31–90 hari; `tidak_aktif` = > 90 hari, atau belum pernah belanja dan terdaftar > 30 hari.
- Telepon disimpan ternormalisasi: hanya digit, awalan `0` diganti `62`, awalan `+` dibuang; unik bila diisi. Data contoh memakai nama dan nomor fiktif (`62812000xxxx`).
- Migration hanya file baru di `supabase/migrations/` (`2026112x...`, berurutan setelah `20261120000500`); tidak mengedit migration lama; tidak dijalankan ke Supabase pengguna; uji hanya di Postgres lokal via `supabase/tests/run.sh`.
- Peran: `pemilik` semua; `kasir` pelanggan (daftar, tambah, ubah profil, riwayat) tanpa halaman segmentasi; `staf_gudang` **tidak** punya akses pelanggan. Data pribadi (telepon, email, alamat) hanya terbaca `pemilik`/`kasir`.
- Fungsi `security definer` memakai `set search_path = public, pg_temp`. Tulis tabel hasil hitung hanya lewat RPC; `customers` memakai hak tulis per kolom.
- Setiap tugas: tes gagal dulu, lalu implementasi; akhir tugas `npm test` + `npm run build` + `npm run lint` (dan `run.sh` untuk tugas SQL) lulus; commit berakhiran trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` dan `Claude-Session: https://claude.ai/code/session_01NjswzVeNpJvCu4pynPEeRZ`.
- Branch kerja: branch baru dari `main` (nama `claude/tahap3-crm`); PR ke `main` di akhir tahap; push/PR hanya sesuai permintaan pengguna.

## Review Focus

- Transaksi dengan pelanggan memperbarui poin, total belanja, jumlah transaksi, belanja terakhir, dan tier **dalam transaksi yang sama**; checkout yang gagal (stok kurang, bayar kurang) tidak mengubah pelanggan — Task 2.
- **Kirim ulang** dengan kunci idempotensi yang sama tidak memberi poin dua kali; kunci yang sama dengan pelanggan berbeda ditolak — Task 2.
- **Dua kasir** menjual ke pelanggan yang sama bersamaan: hitungan pelanggan = jumlah semua transaksi, tidak ada pembaruan yang hilang — Task 2 (skrip konkurensi).
- Batas: belanja Rp9.999 vs Rp10.000; total kumulatif tepat Rp500.000 (silver) vs Rp499.999, tepat Rp2.000.000 (gold) — Task 1 dan Task 2.
- Telepon yang sama dalam format berbeda (`0812-3456-7890`, `+62 812 3456 7890`) ditolak sebagai duplikat; telepon kosong boleh banyak — Task 1.
- Pelanggan nonaktif tidak bisa dipilih di kasir (RPC menolak); penjualan tanpa pelanggan (tamu) tetap berjalan seperti Tahap 2 — Task 2.
- Kasir tidak dapat mengubah poin/total/tier langsung dan tidak dapat membuka segmentasi; staf gudang tidak melihat pelanggan sama sekali — Task 1 dan Task 5.
- Kasir yang membuka riwayat belanja pelanggan melihat transaksi dari semua kasir (bukan hanya miliknya), tetapi tetap tidak bisa membaca `sales` kasir lain secara langsung — Task 3.
